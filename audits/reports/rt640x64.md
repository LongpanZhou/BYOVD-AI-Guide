## Entry surface

Pure NDIS 6.40 miniport (`NdisMRegisterMiniportDriver` import at `0x1400a8928`; version strings `0x1400a91e0`). Import-name table (`0x1400a857a`–`0x1400a8da6`) is definitive and contains **no `IoCreateDevice`, `IoCreateDeviceSecure`, `IoCreateSymbolicLink`, no NDIS `NdisMRegisterDevice`/`NdisRegisterDeviceEx`, no WDF**, and no security-DDI strings (`SDDL`/`D:P`/`GA;;;` absent from the whole string inventory). The driver creates **no control device, no device interface, no symbolic link** — the only openable object is the NDIS-created adapter device (`\Device\<service>` owned by ndis.sys, OS default admin/system DACL). **No unprivileged user-openable surface → short-form.**

## Memory-write analysis

- **Privileged instructions:** instruction sweep over all 618 functions → only `MOV Rxx,CR8` **reads** (140 hits — inline IRQL save pattern around spinlocks). **No WRMSR/RDMSR/LGDT/LIDT/SGDT/SIDT/RDPMC, no CR0/CR3/CR4 writes, no DR7**.
- **Mapping plane:** 10× `MmMapLockedPagesSpecifyCache` (callers `140015058`, `140015a94`, `140015b9c`, `14005c45c`, `14005c5c8`, `14005c73c`, `14005c8d4`, `140077968`, `140098b20`, `1400995c8`) — every site is the identical shared-memory pattern `(MDL, KernelMode=0, MmNonCached=1, NULL, no-bugcheck, MdlMappingNoWrite=0x40000010)` on **NDIS-owned packet/shared-memory MDLs** (e.g. `FUN_140015a94` walks the MDL chain at `param_2+0x20` of an NDIS NET_BUFFER; total copy gated by adapter capacity `*(param_1+0x3678) < len` → skip). No caller-supplied MDL, no user VA anywhere.
- **Object-handle plane:** 2× `ObReferenceObjectByHandle` in the custom-OID SET handler `FUN_140012c90` (Realtek vendor OIDs `0xff816841`/`0xff816842`, asm `0x140013c40`/`0x140013d5d`): `(handle from OID InformationBuffer, 0x10000000, ExEventObjectType, KernelMode=0, &adapterext+0x6b0/0x6b8, NULL)` — out-pointer is a **fixed kernel address** in the adapter extension, not attacker-influenced; KernelMode reference of an event handle is an integrity concern at most, and only via the admin-gated NDIS OID plane.
- **Bus/PCI plane:** `NdisMSetBusData` writes are fixed-offset (0x80/0xb3/0xc/0xd/0xe1) hardware config in init/power paths; not caller-addressable.
- **Registry config plane:** ~90 `NdisReadConfiguration` keywords (`0x1400a13a0`–`0x1400a1e10`) = HKLM admin-settable adapter parameters; no user pointer/length flow.
- **Absent primitives:** `ZwOpenSection`, `\Device\PhysicalMemory`, `MmCopyMemory`, probe-less METHOD_NEITHER (no IOCTL dispatch of its own), unchecked copy/fill lengths (copies are length-gated by NDIS buffer metadata), MSR/GDT/IDT touch.
