**Framework:** WDM (ScpVBus), KMDF (VirtualHID). ScpVBus embeds `WdmlibIoCreateDeviceSecure` (`0x14000A708`) and the SDDL parser, and resolves `IoCreateDeviceSecure` dynamically via `MmGetSystemRoutineAddress`; this is why the PE import table shows only `IoCreateDevice`.

## Verdict

**ScpVBus: NO-WRITE (kernel memory).** The `;;;WD` SDDL **is live** — it is passed to `WdmlibIoCreateDeviceSecure` for every **child PDO** created on demand. The bus FDO itself is created with plain `IoCreateDevice` and **no** SDDL (default admin-only). No handler dereferences a user-supplied kernel pointer or copies a user-controlled length into a kernel buffer; the permissive child PDO exposes only fixed-size HID descriptor/report operations, and the report path is bound to the creating PID.

**VirtualHID: NO-WRITE.** No device object is created at all (no `IoCreateDevice`, no `WdfDeviceCreate`, no `\Device\` literal). It cannot be opened with `CreateFile`; there is no surface to audit beyond the driver entry.

## 1. Device surface — ScpVBus

ScpVBus is a **root-enumerated virtual bus**. `DriverEntry` only installs dispatch pointers (`Bus_IoCtl` = IRP_MJ_DEVICE_CONTROL, `Bus_Internal_IoCtl`, `Bus_PnP`, …); it creates no device.

### 1a. Bus FDO (created in `AddDevice`, not `DriverEntry`)

`FUN_140009B24` (`0x140009B24`):

```c
iVar2 = IoCreateDevice(param_1 /*DriverObject*/, 200, 0, 0x2A, 0x100, 1, &local_res18);
...
iVar2 = IoRegisterDeviceInterface(param_2, &DAT_140004270, 0, _Dst + 0x17);
lVar3 = IoAttachDeviceToDeviceStack(local_res18, param_2);
```

* Name `NULL`, type `0x2A` (`FILE_DEVICE_BUS_EXTENDER`), characteristics `0x100`, exclusive `TRUE`.
* No security descriptor → **default DACL (SYSTEM + Administrators)**.
* Interface GUID `0x140004270` (`GUID_DEVINTERFACE_SCPVBUS`).
* Unprivileged users cannot open the FDO.

### 1b. Child PDO (created on demand, after enumeration)

`FUN_14000A25C` (`0x14000A25C`) is reached from the FDO's `Bus_IoCtl` on **`IOCTL_BUSENUM_PLUGIN_HARDWARE` (`0x2AA004`)** → `Bus_PlugInDevice` → `FUN_14000A25C`. It creates the virtual controller PDO:

```
14000A2C7  48 8B 0B               MOV RCX,[RBX]              ; DriverObject
14000A2D4  41 B9 2A 00 00 00      MOV R9D,0x2A               ; DeviceType
14000A2DA  48 8D 05 9F 9F FF FF   LEA RAX,[0x140004280]      ; &GUID_DEVCLASS_X360WIRED_CUSTOM
14000A2E1  45 33 C0               XOR R8D,R8D                ; DeviceName = NULL
14000A2E4  48 89 44 24 38         MOV [RSP+0x38],RAX         ; arg 8: class GUID
14000A2E9  BA B8 00 00 00         MOV EDX,0xB8               ; extension size
14000A2F2  48 8D 05 A7 9F FF FF   LEA RAX,[0x1400042A0]      ; &UNICODE_STRING(SDDL)
14000A2F9  48 89 44 24 30         MOV [RSP+0x30],RAX         ; arg 7: SDDL
14000A2FE  C6 44 24 28 00         MOV byte [RSP+0x28],0    ; Exclusive = FALSE
14000A303  C7 44 24 20 80 01 00 00 MOV dword [RSP+0x20],0x180 ; characteristics
14000A30B  E8 F8 03 00 00         CALL 0x14000A708            ; WdmlibIoCreateDeviceSecure
```

The SDDL `UNICODE_STRING` is at `0x1400042A0` (`Length=0x7E`, `MaximumLength=0x80`, `Buffer=0x1400042B0`). The buffer decodes to:

```
D:P(A;;GA;;;SY)(A;;GRGWGX;;;BA)(A;;GRGWGX;;;WD)(A;;GRGWGX;;;RC)
```

Effective DACL on the child PDO:

| SID | Access |
|---|---|
| `SY` | `GA` GENERIC_ALL |
| `BA` | `GRGWGX` read/write/execute |
| `WD` **Everyone** | `GRGWGX` **read/write/execute** |
| `RC` | `GRGWGX` read/write/execute |

The PDO is created with `DeviceName = NULL` and `FILE_AUTOGENERATED_DEVICE_NAME`; it is reachable through its device interface (`GUID_DEVCLASS_X360WIRED_CUSTOM` / the USB device interface registered when it starts), not through a fixed `\Device\` name.

**Answer to Q6:** the permissive descriptor is **not** passed at `DriverEntry`. The FDO is created in `AddDevice` with plain `IoCreateDevice` (no SDDL, admin-only); the SDDL-secured child PDOs are created later, only when the bus receives `0x2AA004` from a client. So a fresh boot has no world-openable ScpVBus device until something plugs a virtual controller.

## 2. IOCTL table — ScpVBus

### 2a. FDO (`FUN_140001D18`, `0x140001D18`)

| IOCTL | Function | Access | Behaviour |
|---|---|---|---|
| `0x2AA004` | 0x801 | WRITE | `Bus_PlugInDevice` → `FUN_14000A25C` (create PDO with SDDL) |
| `0x2AA008` | 0x802 | WRITE | unplug; PID-gated (`CallingProcessId` or force flag) |
| `0x2AA00C` | 0x803 | WRITE | eject |
| `0x2AE010` | 0x804 | RW | submit input report (0x1C bytes) → `FUN_140001FA8` |
| `0x2AE404` | 0x901 | RW | is-device-plugged (4-byte in/out) |
| `0x2AE408` | 0x902 | RW | get creating PID (1-byte out) |
| `0x2AE40C` | 0x903 | RW | empty slots (4-byte in/out) |
| `0x2AE410` | 0x904 | RW | version (`*out = 0x1712`) |

All are `METHOD_BUFFERED`. Each case checks the exact `InputBufferLength`/`OutputBufferLength` (e.g. `if ((iVar1 == 0x10) && (*piVar6 == 0x10))` for plug-in, `if (iVar2 == 4)` for report/version) and the first dword `Size`/serial inside the structure.

`0x2AE010` (`FUN_140001FA8`, `0x140001FA8`) additionally enforces:

```c
iVar8 = PsGetCurrentProcessId();
if (*(int *)(puVar13 + 0x16) != iVar8) return 0xC0000022;   // ACCESS_DENIED
...
for (i = 0; i < 0x14; i++) if (ctx->serial[i] != in[i+8]) goto mismatch;
```

so only the process that plugged the controller can submit reports.

### 2b. Child PDO (`FUN_1400015D0`, `0x1400015D0`)

| IOCTL | Function | Method | Access | Behaviour |
|---|---|---|---|---|
| `0x220003` | 0x800 | **NEITHER** | ANY | write HID report descriptor (fixed template) |
| `0x220007` | 0x801 | BUFFERED | ANY | descriptor/feature query |
| `0x220013` | 0x804 | **NEITHER** | ANY | write `dword 3` (status/version) |

The `0x220003` branch writes a fixed Xbox 360 HID descriptor template at offsets `+0x2C … +0x88` (`0x5DFF`, `0x81`, `0xFFFF`, `0x1810040`, `0x1000`, `0x1820020`, …). Values are constants; no user payload is used.

## 3. Write sinks

* **`0x220003` / `0x220013` descriptor buffer** (`0x140001EFE`–`0x140001F4D`): fixed constants written at fixed offsets from a pointer loaded out of the I/O stack parameters. There is **no** `ProbeForWrite`/`ProbeForRead` import in the image.
* **Report path** (`FUN_140001FA8`): copies the 0x1C-byte report into a `PDO_DEVICE_DATA` ring buffer and completes the matching pending read IRP; bounded and PID-gated.
* **`0x2AA004`** allocates `ExAllocatePoolWithTag(0, 0x6C, 'ScpV')` for the PDO's hardware-ID string and copies a fixed literal; no user length.
* No `MmMapIoSpace`, `MmCopyMemory`, `ZwMapViewOfSection`, `MmMapLockedPages*` or arbitrary kernel pointer.
* The child PDO is a world-RWX device, but its handlers only produce HID reports/descriptors.

## 4. Validation gaps

* **`0x220003` destination provenance.** The destination is read from the I/O stack parameters (`[stack+8]`), and the code writes ~0x88 bytes without a length check. Static resolution of that field is ambiguous in this build: the same function also reads the IoControlCode from `[stack+0x18]`, while the WDK layout puts `OutputBufferLength` at `+8`. If the field is truly `OutputBufferLength` (a 32-bit value), the worst case is a low-address/NULL-page write (DoS), not a kernel-address write; if it is a raw `METHOD_NEITHER` buffer pointer, it is a fixed-content write to an attacker-chosen address. **This one branch needs dynamic confirmation.**
* `0x2AA004` requires `inLen == sizeof(BUSENUM_PLUGIN_HARDWARE)` and `((PBUSENUM_PLUGIN_HARDWARE)buf)->Size == inLen`; good.
* `0x2AE010`/`0x2AE404`/`0x2AE408`/`0x2AE40C` require exact 4-byte/1-byte lengths; good.
* The FDO is admin-only, so all bus-management IOCTLs are unreachable by a standard user.

## 5. Setup required

* **FDO:** composition — the driver must be installed as a root-enumerated bus (`ScpVBus` service + `ROOT\SCPVBUS` devnode).
* **Child PDO:** devnode/composition — a client (SCP service or a reimplementation) must open the FDO as an administrator and send `0x2AA004`; only then does the Everyone-RWX child appear.
* No hardware is required (the bus is virtual), which makes this family more interesting than the FTDI/HID ones for a "no extra hardware" test — but the bus FDO still requires an administrator to plug the child.

## 6. Next dynamic test

1. Install ScpVBus, open `\\.\SCPVBUS` (or the `GUID_DEVINTERFACE_SCPVBUS` interface) as **administrator**, send `0x2AA004` with a valid `BUSENUM_PLUGIN_HARDWARE` (SerialNo 1) to create a child.
2. As a **standard user**, enumerate `GUID_DEVCLASS_X360WIRED_CUSTOM` / the USB interface and open the child PDO; confirm the world-RWX DACL allows it.
3. Under KD, break at `0x140001EFE` and log `[r8+8]` vs. the caller's `Type3InputBuffer` and `UserBuffer` for `0x220003`. Then call `0x220003` with a user buffer and with a kernel address:
   * if the kernel-address call faults/bluescreens → the branch is a fixed-content arbitrary write (WRITE-LOW);
   * if it is rejected/never reached → close as NO-WRITE.
4. Send `0x2AE010` from a *different* process and confirm `STATUS_ACCESS_DENIED` (PID binding).

## 7. VirtualHID (`VirtualHID_6BD8F1E1.sys`)

**Verdict: NO-WRITE (no device surface).**

* x64 KMDF driver, 26,768 bytes, imports only `ExAllocatePoolWithTag`, `IofCompleteRequest`, `KeBugCheckEx`, `KeInitializeEvent`, `KeSetEvent`, `KeWaitForSingleObject`, `RtlCopyUnicodeString`, `WdfVersionBind*`.
* Strings: `TurtleBeach\VirtualHID`, `TurtleBeach`, `Virtual HID Device`, `VHID_CONTEXT`. No `\Device\`, no `\DosDevices\`, no SDDL literal.
* No `IoCreateDevice`, no `WdfDeviceCreate`, no `WdfControlDeviceInitAllocate`, no device interface, no queue. The driver never creates an object that `CreateFile` could open.
* The only writes are into the `VHID_CONTEXT` pool allocation at fixed offsets; no user-controlled pointer or length.

**Next dynamic test:** none needed for the unprivileged case — the driver cannot be opened. If the companion (Turtle Beach) service is present, verify with `!devobj`/`!drvobj` that no device object exists for `VirtualHID`.

---

**Bottom line:** ScpVBus's permissive SDDL is real but applies only to on-demand child PDOs whose handlers are fixed-size HID operations; the bus FDO is admin-only. VirtualHID has no device at all. No kernel memory-write primitive was found in either.
